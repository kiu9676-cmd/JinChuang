# 使用手册

[返回项目首页](../README.md)

## 两台设备互传

1. 在两台设备上启动近传，连接同一个可信的 Wi-Fi 或有线路由器。
2. 在会话列表里选择对方。未自动发现时，点「+」，填对方 IP，例如 `192.168.1.20` 或 `192.168.1.20:8765`；可以先点「检测连接」。
3. 输入文字，或将附件拖进会话。文件先进入待发送列表，确认后再点「发送」。

从 v1.6.2 起，复制截图或图片后，可在会话里按 `Ctrl+V` / `⌘V` 把它加入待发送区；纯文字仍按正常方式粘贴。

聊天卡片里的「下载」可保存文件。「另存为」和原生文件夹选择需要桌面模式。整目录传输会保留相对目录结构。

## 暂停、继续、取消

双方都使用 v1.6.1 或更新版本时，在单聊文件卡片或左侧「传输」页操作：

- **暂停**：当前分块结束后停下。两端重启后仍保留已确认的进度。
- **继续**：重新查询接收端确认的字节数，只补传未确认的部分。完成后检查 SHA-256，通过才生成最终文件。
- **取消**：只清理未完成的临时数据。如果接收端暂时不在线，等待它上线后点「重试清理」。
- **重试**：网络断开时，可在「传输」页继续。进度达到 100% 但仍显示「正在校验」时，请等校验结束。

文件夹、群聊和较旧对端仍走原有方式，不支持以上完整的续传控制。发送前会写入本机缓存，发送盘和接收盘均需留出空间。

## 查聊天记录

点会话右上角放大镜，或按 `Ctrl+F` / `⌘F`。搜索只针对当前会话中保留的记录，可筛选消息、图片、文件或文件夹。点击结果定位到原消息。

## 数据存放与迁移

| 路径（默认） | 内容 |
| --- | --- |
| `data/config.json` | 本机名称、头像、端口和保存路径等设置 |
| `data/peers.json` | 设备地址和备注 |
| `data/messages.json`、`data/groups.json` | 消息与群聊 |
| `data/downloads/` | 默认接收目录 |
| `data/cache/` | 发送缓存，部分已发送附件的历史下载也使用这里 |
| `data/transfers-in/`、`data/transfers-out/` | 续传任务和确认进度 |
| 接收目录中的 `.jinchuan-partials/` | 尚未完成的分块数据 |

便携版默认使用 EXE 同级的 `data/`，源码模式默认使用仓库目录下的 `data/`。迁移或备份前先退出近传；自定义接收目录需要单独备份。请在可写目录运行。

## 常见问题

- **诊断通过但文件发送失败**：诊断仅验证对方能应答；请在「传输」页查看具体错误。如提示接收目录不可用，请在接收端检查目录权限。发送过程中显示「正在读取本机文件」表示正在分块写入本机缓存，还没开始向对方发送。
- **能看到好友但发不了文件**：在「好友资料」里运行连接诊断。访客网络或路由器设备隔离可能阻止设备直连。
- **端口被占用**：从托盘真正退出旧版。默认端口是 `8765/TCP`（聊天、传输与控制）和 `53317/UDP`（发现）。改了 TCP 端口后，添加时需写 `IP:端口`。
- **仅启动本机服务**：`python server.py --no-browser`。独立开发实例可指定 `--http-port 18765 --udp-port 54317 --data-dir ./data/test-a`。
- **检查更新**：桌面版可在「设置 → 更新」检查 GitHub Release，下载时显示实时速度。v1.6.4 会在慢连接且源支持分段时使用并行下载，仍从原发布源获取。源码模式用 `git pull` 更新后重启。
- **大文件传得慢**：两端都用 v1.6.4 可减少往返确认的次数。若仍慢，先区分「正在读取本机文件」与「传输中」；前者主要取决于本机磁盘，后者还受两端的实际网络和接收磁盘影响。

提交问题前请删掉截图和日志中的本机用户名、真实设备名、IP、聊天内容和文件路径。
